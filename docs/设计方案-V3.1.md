# ESP32-P4 智能终端：设计方案（V3.1 精简版）

> 基于 V3.0（2026-11-19，584 行）精简，2026-11-20 更新。
> **范围变更**：取消 S3 触摸控制、S5 云同步、`cloud-main` 接入、S7 72 小时稳定性验收。
> 现定位为**只读监控终端**：局域网内汇聚泰山派 3M 与 Windows 主机的状态，一屏查看，不下发控制。
> 原文完整版见同目录 `设计方案-V3.0.md.bak-20261120-0956`。

---

## 1. 定位与边界

| 项 | 结论 |
|---|---|
| 主目标 | ESP32-P4 独立开机进入 Dashboard，电脑关机也能用 |
| 监控对象 | `taishan-3m`（RK3576 / Ubuntu）、`windows-main`（Windows 11） |
| 数据方向 | 单向：Agent → 泰山派 Mosquitto → ESP32，终端只订阅 |
| 不做 | 触摸下发控制、任意 Shell、root SSH、云端同步、公网暴露、USB 副屏（暂缓） |
| 状态要求 | 在线 / 离线 / 数据过期 / 未知 四态必须区分，不拿 0 或旧值冒充 |

**复用原则**：板级驱动用乐鑫 BSP，GUI 用 LVGL 9.6，网络用 ESP-IDF 以太网与 esp-mqtt，Broker 用 Mosquitto，Windows 采集用 psutil；只自研 UI、消息 schema 和状态判定，不从零写 DSI/GT911/MQTT 协议栈。

## 2. 硬件与环境

| 项 | 值 |
|---|---|
| 开发板 | ESP32-P4-Function-EV-Board **V1.5.2**，芯片 rev **v1.3**（非 P4X） |
| Flash / PSRAM | 16 MB QIO@80 MHz / 32 MB |
| 屏幕 | 1024×600 EK79007（MIPI-DSI），GT911 触摸（I2C：SCL=IO8，SDA=IO7） |
| 背光 / 复位 | GPIO26 / GPIO27 |
| 串口 | Windows 侧 **COM5**（USB-Serial/JTAG） |
| ESP-IDF | **v5.4.4**（`~/esp-idf`） |
| 工程 | `firmware/esp32-terminal`，app 分区 4 MB @ `0x20000` |
| 固件 | `0.5.5-s2e`，app 约 1.53 MB，余量 63% |

**以太网接线**（`eth_link.c`，与 IDF P4 默认一致）：

| 信号 | GPIO | 信号 | GPIO |
|---|---|---|---|
| MDC | 31 | TXD0 | 34 |
| MDIO | 52 | TXD1 | 35 |
| PHY_RSTN（低有效） | 51 | CRS_DV | 28 |
| RMII_CLK（IP101→P4，50 MHz） | 50 | RXD0 | 29 |
| TX_EN | 49 | RXD1 | 30 |

PHY 地址 **1**；IP101 自带 25 MHz 晶振并向 P4 输出 50 MHz，时钟方向必须是 `EMAC_CLK_EXT_IN`。网络初始化只 `xTaskCreate`，PHY 复位、自协商、DHCP 全在后台，UI 只读快照，绝不等待网络。

## 3. 网络与地址

| 设备 | 地址 | 连接 |
|---|---|---|
| 路由器 | `192.168.0.1` | 网关 |
| 泰山派 3M | `192.168.0.156`（`end0`） | 有线千兆 |
| ESP32-P4 | `192.168.0.100` | RJ45，DHCP |
| Windows 主机 | 同网段 | 有线/Wi-Fi |
| Hub | `0.0.0.0:1883`，Mosquitto 2.0.18，禁止匿名 | — |

路由器上给 `.156` 和 `.100` 做 **DHCP 地址保留**（待办）；ESP32 的 MQTT 地址按 mDNS（`squirrel-lckfb.local`）→ 静态兜底三级解析。

## 4. 协议与数据能力

主题（权威定义见 `../protocol/topics-v1.md`）：

```text
hub/v1/devices/{device_id}/status     # 在线状态 + LWT
hub/v1/devices/{device_id}/metrics    # 指标帧
```

帧内字段：`schema_version`、`device_id`、`timestamp_utc`、`valid_for_seconds`、`payload`。单位统一为百分比 / 摄氏度 / 字节。

| 字段组 | 泰山派 | Windows | 屏幕落点 |
|---|---|---|---|
| cpu | ✅ 8 核 + load1/5/15 | ✅ 10 物理 / 16 逻辑 | CPU 大卡左列、负载卡 |
| memory | ✅ | ✅ | 内存卡 |
| temperature | ✅ 6 温区 | ❌ | 温区卡（无进程数据时） |
| disk / disks[] | ✅ `/` | ✅ C: 主 + D:/S: 分区 | 磁盘卡 |
| gpu | ❌ | ✅ RTX 4060：利用率/温度/显存 | CPU 大卡右列 |
| processes | ❌ | ✅ 前 3，按内存降序 | 进程卡 |
| network | ❌ | ✅ 收发速率 | 网络卡 |
| containers | ✅ schema 4 | ❌ | 容器列（无 GPU 时） |
| services | ✅ | ✅ | 不再上屏 |
| uptime | ✅ | ✅ | 负载卡标题可切 |

Linux 端发 schema 4，Windows 端发 3，ESP32 收 1–4。所有缺失字段显示 `--` + 原因（等待数据 / 已过期 / 未上报）。

**在线判定**：心跳 + LWT + `timestamp_utc` 三重校验；`retained` 只当最后缓存，必须看时间；Broker 掉线时不能把旧“在线”留成绿色。超时窗口 10–15 s。

**刷新策略**：CPU/内存 2 s，温度 5 s，磁盘 30 s，状态 5 s；UI 数据驱动局部刷新，不整屏重绘。

## 5. 系统拓扑

```text
        ┌──────────────────────────────┐
        │ 泰山派 3M（192.168.0.156）    │
        │ Mosquitto + Agent + systemd   │
        └───────┬──────────────┬───────┘
                │ MQTT         │ MQTT
     ┌──────────▼───────┐  ┌───▼────────────────┐
     │ ESP32-P4 终端     │  │ Windows 11 Agent   │
     │ 1024×600 LVGL     │  │ psutil / nvidia-smi│
     └──────────────────┘  └────────────────────┘
```

故障隔离：Windows 关机 → 屏幕显示离线，其余正常；泰山派故障 → 终端 UI 仍可进，监控区显示“Hub 不可用”，不假装成功。

## 6. ESP32 固件

```text
main/
├── main.c               # 板信息 → 显示 → UI → 背光 → 网络/MQTT → 挂解析器
├── app_ui.c/.h          # 状态栏（全设备汇总灯）+ 页签 + 通用控件
├── app_ui_internal.h    # 配色、控件句柄、槽位声明
├── ui_page_overview.c   # 4 张设备摘要卡 + 网络卡 + MQTT 卡
├── ui_page_monitor.c    # ◀ ▶ 切设备 + 5 张能力自适应卡
├── ui_page_placeholder.c# 设置页（占位，待做亮度/诊断）
├── eth_link.c/.h        # EMAC + IP101 + DHCP，只读快照
├── mqtt_link.c/.h       # 三级地址解析、自管重连、多回调
├── device_registry.c/.h # device_id → 固定槽 0..3
├── device_metrics.c/.h  # metrics 解析，schema 1–4
├── device_status.c/.h   # status + LWT，在线判定
└── fonts/               # cjk_16/20/28 生成物，必须入库
```

初始化顺序：`device_registry_init()` → `device_metrics_init()` → `device_status_init()`，且都在收包前完成；消息不缓存。

**三页**

1. **总览**：4 张 222×260 摘要卡（未接入灰显“未接入设备”）+ 网络卡 + MQTT 卡；状态灯为“全部在线才绿”的汇总。
2. **监控**：页头 ◀ ▶ + 设备名 + 四态；五张卡按能力二选一——`480×240` CPU 大卡（右列 GPU 或容器）、`464×240` 右侧卡（进程或温区）、`304×140` 左下（网络或负载）、内存卡、磁盘卡。
3. **设置**：当前为占位页；计划放亮度、以太网状态、固件版本、诊断日志。

**构建与烧录**：`build-s2a.sh`（叠加 `sdkconfig.secrets`）→ 复制到 `C:\Users\haha4\p4-s0\` → COM5 烧 `0x2000` / `0x9000` / `0x20000`。中文文案改动后必须重跑 `tools/gen_cjk_font.sh`。坑位清单见 `项目交接.md` 第 6 节。

## 7. 泰山派服务

| 服务 | 作用 | 状态 |
|---|---|---|
| Mosquitto 2.0.18 | 本机 Broker，`0.0.0.0:1883`，禁止匿名 | ✅ |
| `taishan-hub-agent` | 每 10 s 采 CPU/内存/温度/磁盘/uptime；15 s 采 `docker ps` 容器 | ✅ systemd 常驻 |
| Control API（FastAPI） | 曾计划的触摸控制入口 | ❌ 取消 |
| SQLite 历史 / 云同步 | 历史采样、上云 | ❌ 取消 |

账号 ACL：`taishan-agent` 只写自己的 metrics/status；`esp32-terminal` 读 `hub/v1/devices/#`、写自身；`ops` 全权。凭据在 `/etc/taishan-hub/credentials.env`（不入库、不打印）。

## 8. Windows Agent

采集：CPU（总/每核）、内存、磁盘 C/D/S、GPU（`nvidia-smi`：利用率/温度/显存）、进程前 3（按内存降序）、网络收发、开机时长。

限制：风扇转速取不到（`Win32_Fan` 空、`nvidia-smi fan.speed=N/A`、Acer EC 私有），界面不显示风扇；`Get-NetAdapterStatistics` 约 2.6 s、`Win32_PerfFormattedData` 约 5.1 s，已避开。

部署：计划任务 `TaishanHubWindowsAgent` 常驻，日志 `C:\ProgramData\taishan-hub\logs\windows-agent.log`。

## 10. 本期验收

1. 不接 Windows 也能独立开机进入 Dashboard。
2. 显示、触摸正常；亮度可调；能进设置页查看网络与版本。
3. 屏幕上显示的是**真实** CPU、内存、温度、磁盘、GPU 数据，与源端一致。
4. 在线 / 离线 / 数据过期 / 未知 四态判断正确，拔网线、关 Windows 后显示符合预期。
5. 泰山派重启、ESP32 网线拔插后能自动恢复订阅。
6. 断公网不影响本地监控（本方案不含公网依赖）。
7. 固件有版本记录与可回退包（`p4-s0` 三件套 + git tag）。
