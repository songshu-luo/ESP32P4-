## 0. 一句话说明项目

ESP32-P4 + 7 寸屏做成一个**独立智能终端**（不依赖 Windows 开机），
通过局域网从**泰山派 3M（RK3576 / Ubuntu）** 拉取真实设备状态（CPU/内存/温度/磁盘），
并在屏幕上做**受控**的设备操作；Windows 11 和云服务器作为可选的被监控节点。

正式方案见：`../ESP32-P4_智能终端与多设备协同系统_重写最终方案_V3.0.md`（**权威文档，冲突时以它为准**）。

### 3.2 各文件职责

- **`main.c`**：`log_board_info()` 打印芯片 revision / Flash / PSRAM / LCD；
  `bsp_display_start()` → `app_ui_build()` → `bsp_display_brightness_set(80)` →
  `eth_link_start_async()` → `mqtt_link_start_async()` → `device_metrics_init()` +
  `device_status_init()` → 用 `mqtt_link_add_data_cb()` 把两个解析器挂上。
  **顺序很关键**：解析器必须在开始收包前初始化，否则消息被直接丢弃（不缓存）。
- **`app_ui.c`**：4 个每 500 ms 轮询的快照刷新函数
  （`net_poll_cb` / `mqtt_poll_cb` / `status_poll_cb` / `metrics_poll_cb`）+
  1 个 1 s 的 `uptime_cb`。UI 线程只读互斥快照，**不解析 JSON、不等网络**。
- **`mqtt_link.c`**：三级地址解析（mDNS 名 → 裸名 → 写死 IP）、自管重连
  （关掉 esp-mqtt 的 auto reconnect，为了每次重连都重新解析）、
  按主题后缀计数（`/metrics`、`/status`）、把每条消息转发给所有注册的回调。
- **`device_metrics.c` / `device_status.c`**：在 esp-mqtt 任务里解析，
  互斥快照给 UI；新鲜度用「到达时刻 + `valid_for_seconds`」，**不与 `timestamp_utc` 比对**
  （ESP32 无 RTC、未接 SNTP，time() 停在 1970）。

### 3.4 以太网实现要点（`eth_link.c`）

**硬件映射**（来自官方原理图 v1.5.2 第 2 页 P4 引脚页 × 第 5 页 PHY 页，与 IDF P4 默认值一致）：

| 信号 | GPIO | | 信号 | GPIO |
|---|---|---|---|---|
| MDC | 31 | | TXD0 | 34 |
| MDIO | 52 | | TXD1 | 35 |
| PHY_RSTN | 51（低有效）| | CRS_DV | 28 |
| RMII_CLK（IP101 → P4, 50MHz）| 50 | | RXD0 | 29 |
| TX_EN | 49 | | RXD1 | 30 |

PHY 地址 **1**（PHY_AD0 上拉 / PHY_AD3 接地）。

**架构约束**（对应方案 §6.3「启动不得阻塞在网络」）：
`eth_link_start_async()` 只 `xTaskCreate` 就返回；PHY 复位、自协商、DHCP 全在后台；
UI 线程只调 `eth_link_get_status()` 拿互斥锁保护的快照，**绝不等待网络**。

**时钟方向**：IP101 自带 25MHz 晶振，向 P4 输出 50MHz REF_CLK →
必须是 `EMAC_CLK_EXT_IN`，**不能**选 `EMAC_CLK_OUT`（否则两边都推时钟，冲突）。

## 4. 已踩过的坑（新对话请勿重犯）

1. **`ETH_LINK_UP` / `ETH_LINK_DOWN` 枚举重名。**
   `components/hal/include/hal/eth_types.h` 里已有
   `typedef enum { ETH_LINK_UP, ETH_LINK_DOWN } eth_link_t;`
   本项目枚举统一用 `ETH_STATE_*` 前缀。

2. **LVGL 9 的 `lv_indev_active()` 在定时器回调里恒为 `NULL`。**
   它只返回「当前正在处理事件」的 indev。取触摸设备必须用
   `bsp_display_get_input_dev()`。

3. **改了 `sdkconfig.defaults` 不生效** —— 必须 `rm sdkconfig` 再 build
   （`build-s2a.sh` 已按时间戳自动处理）。否则旧值一直沿用。

4. **LVGL 9.6 弃用了一批 flag API。**
   `lv_obj_clear_flag` / `lv_obj_remove_flag` / `lv_obj_add_flag` 都会告警，
   改用专用的 setter：`lv_obj_set_scrollable(obj, false)`、
   `lv_obj_set_clickable(obj, false)`、`lv_obj_set_hidden(obj, true)` 等。

5. **WSL 里 `git clone github.com` 超时**（raw/api/components.espressif.com 正常）。
   上游 zip 由用户在 Windows 侧下载后放进 WSL。`~/esp32_workspace/example` 是
   esp-bsp 的**非 git 副本**，拿不到 commit SHA。

6. **PowerShell 直接读 `\\wsl.localhost\...` 路径会失败** —— 固件必须先
   复制到 `C:\Users\haha4\p4-s0\` 再烧。

7. **PowerShell 续行符 `` ` `` 必须是行尾最后一个字符**，漏了命令会被截断，
   esptool 报 `Missing argument '<address> <filename>...'`。**用单行版命令。**

8. **烧录地址与旧工程不同**：分区表 **0x9000**（旧 0x8000），app **0x20000**（旧 0x10000）。

9. **kconfig 的 string 项必须带引号。** `sdkconfig.secrets` 里写成
   `CONFIG_TERMINAL_MQTT_PASSWORD=abc123` 会被当成非法输入、**静默回退成默认值**，
   表现为「构建成功、烧录成功、就是连不上 Broker」。必须写成
   `CONFIG_TERMINAL_MQTT_PASSWORD="abc123"`。`build-s2a.sh` 末尾会检查这一点。

10. **`sdkconfig.defaults` 里的密码是空串，真实密码在 `sdkconfig.secrets`。**
    必须用 `SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.secrets"` 构建，
    否则编出来的固件密码为空（现象是 `AUTH FAIL` 或 `connect refused`）。

11. **不用装 `espressif/mdns` 组件。** IDF 5.4.4 的 lwIP 自带
    `CONFIG_LWIP_DNS_SUPPORT_MDNS_QUERIES`，`getaddrinfo("xxx.local")` 会直接发
    一次性组播查询。实测泰山派 avahi 会以单播回 A 记录（3 s 内）。
    但 **Windows 的 `nslookup xxx.local` 查不到**，别拿它判断。

12. **不要用 `lv_font_montserrat_*` 显示中文** —— 它只有拉丁字母，中文会显示成
    方块。中文一律用 `main/fonts/` 下的 `lv_font_cjk_16/20/28`。
    **改了任何中文文案后必须重跑 `bash tools/gen_cjk_font.sh`**，否则新字变方块。
    脚本会扫 `main/` 下所有 .c/.h 的**字符串字面量**（自动跳过注释）。

13. **`lv_font_conv` 生成的字体默认 `#include "lvgl/lvgl.h"`，本工程编译不过。**
    必须加 `--lv-include lvgl.h` 参数，生成的才是 `#include "lvgl.h"`。
    `gen_cjk_font.sh` 已包含此参数。

14. **WSL 里直接执行 Windows 的 `npx.cmd` 会报**
    `unexpected EOF while looking for matching '`'`（.cmd 是批处理 + CRLF）。
    必须用 `node.exe` 直接跑 `npx-cli.js` / `lv_font_conv.js`。脚本已处理。

15. **注释里不能出现 `*/`。** 曾在 `mqtt_link.h` 注释里写
    `hub/v1/devices/*/metrics`，其中的 `*/` 提前结束了块注释，
    导致后续字段被当代码解析，报一连串 `unknown type name 'metrics'`。

16. **cJSON 解析不要先 memcpy 到栈上。** esp-mqtt 默认任务栈只有 6 KB，
    再开 4 KB 栈缓冲会溢出。`cJSON_ParseWithLength(data, data_len)` 是按长度
    解析的有界接口，**不要求 NUL 结尾**，直接用它。

17. **`esp-mqtt` 的数据回调只有 1 个槽位时就够用，但第二个模块要接入必须改成数组。**
    现在是 `mqtt_link_add_data_cb()`，最多 4 个，各模块自己按主题过滤。

18. **LVGL 9 里 `flex_flow` / `size` 也是样式属性，`lv_obj_remove_style_all()` 会把它们一起删掉。**
    在页签栏上这样做会让三个按钮全部叠在原点（屏幕上是一团字）；
    在 `lv_tabview_add_tab()` 返回的页面上这样做会让页面缩回默认尺寸（卡片被裁剪/叠在一起）。
    **规则**：`remove_style_all` 只能用在叶子控件上；对容器要逐条覆盖样式，
    已经删过的必须补回 `lv_obj_set_size(page, lv_pct(100), lv_pct(100))`。

19. **`lv_obj_set_hidden()` 在这份 LVGL 9.6 里不存在。** 显隐仍用
    `lv_obj_add_flag/remove_flag(obj, LV_OBJ_FLAG_HIDDEN)`，只有弃用告警，功能正常。

## 7. 安全红线（来自 V3.0 方案第 10 章，任何阶段都不得违反）

- ESP32 **不保存** root SSH 私钥。
- **不暴露**任意 Shell / PowerShell / cmd 命令执行入口。
- 控制动作只能走**授权的 HTTPS Control API**，带白名单、`request_id` 幂等、审计、二次确认。
- ESP32 **不是**根控制器；高风险操作必须由泰山派/Hub 决策与执行。
- MQTT 1883 和 Control API **绝不可**无鉴权暴露到公网；云不是本地控制的硬依赖。
- 高风险命令**不得**用 retained 消息，**不得**在重连后自动补执行。
- 「请求已发送」**绝不**显示成「成功」；必须有最终结果回执。
- 在线判断必须 = 时间戳 + 有效期 + 心跳 + LWT；**不要把缓存里的"在线"当成真的在线**。
- `sdkconfig.secrets`（含真实 MQTT 密码）**绝不入库**。

## 9. 下一步：多设备（S4-a → S2-e → S4-b）

**现状**：固件能显示泰山的全部指标，但整条链路里 `taishan-3m` 是**写死**的——
`device_metrics.c` / `device_status.c` 的主题前缀都是 `hub/v1/devices/taishan-3m/`，
快照也只有一份。要显示「多台设备」，缺的是第二台设备 + 按 `device_id` 索引。

顺序（每一步都有屏幕可见变化，做完停下等验收）：

### 9.1 S4-a Windows Agent（第二台设备上线）

目标：Windows 11 上跑一个后台程序，向 Hub 发布 `hub/v1/devices/windows-main/{status,metrics}`。

- 代码放 `agents/windows/`（目前是空目录）。语言用 **Python 3.11（已确认可用）**。
- **不引入 pip 依赖**：MQTT 客户端用 `paho-mqtt`（已装 2.2.0），
  CPU / 内存 / 磁盘用 `ctypes` 调 Windows API（`GetSystemTimes`、
  `GlobalMemoryStatusEx`、`GetDiskFreeSpaceExW`），不装 `psutil`。
- 温度：Windows 普通进程读不到，按协议给 `null`（`has_*` 纪律，
  屏幕上显示 `--`，绝不编一个数字）。
- 必须实现：**LWT**（`will_set("hub/v1/devices/windows-main/status", offline, retain=True)`）、
  `valid_for_seconds`、`timestamp_utc`、单调递增 `message_id`。
- **Hub 侧要先加 ACL 与凭据**：`services/taishan-hub/mosquitto/acl` 里目前没有
  `windows-agent` 用户。要给 `install-broker.sh` 加一组凭据，
  并限定它**只能写** `hub/v1/devices/windows-main/{status,metrics}`。
  凭据只写进 `/etc/taishan-hub/credentials.env`，**不进仓库、不打印到对话里**。
- 开机自启：先手动跑通，再谈任务计划程序（S4-a 收尾时做）。

### 9.2 S2-e 多设备索引（总览页出现第二张设备卡）

- `device_metrics` / `device_status` 改成**按 `device_id` 索引的小表**
  （固定容量，例如 4 台；未知 ID 超出容量就丢弃并在日志里记一次）。
- 主题解析：`hub/v1/devices/{id}/metrics` 里把 `{id}` 切出来，不再写死。
- 总览页：设备摘要卡横排，每台一行大字（名称 / 在线灯 / CPU / 内存 / 温度）。
  泰山派和 Windows 各一张。
- 状态栏的灯改成「**全部设备在线才绿**」，有任一台离线就红并写明是哪台。

### 9.3 S4-b 监控页设备切换键

- 监控页标题行加 `◀ 泰山派 ▶` 切换键（两个可点箭标 + 设备名）。
- 切换只改「当前查看的是哪台」，数据仍然全部来自同一份多设备快照。
- Windows 设备没有温区和 systemd 服务：对应卡片显示「该设备未上报此项目」，
  **不显示空的 `--` 网格**。

### 9.4 暂缓项

- **S3 安全控制**：按「终端只做查看」的决定暂缓。方案里的白名单、`request_id`
  幂等、审计、二次确认等设计仍然有效，将来恢复时再实现。
- **控制页**：已从固件删除，不恢复。
- **S6 副屏 / S5 云同步 / S7 72 小时稳定性**：更后面的事。
