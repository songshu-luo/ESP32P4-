# S1 以太网接入记录

> 日期：2026-11-19
> 阶段：S1（IP101GRI + ESP32-P4 EMAC RMII + RJ45，DHCP）

## 1. 硬件确认（原理图 v1.5.2 文本提取）

板载以太网是 **IP101GRI**（第 5 页 `ETHERNET PHY IC`），经 P4 内置 EMAC 的 RMII 接口
接 RJ45（HR913550A 带隔离变压器），10/100M。厂商原理图注释：

- `COL/RMII` 引脚默认 **1 = RMII Mode**
- `PHY_RSTN` 低有效，**拉低至少 10ms** 才能完成复位
- `PHY_AD0` 上拉 … → PHY 地址 **1**

BSP 5.2.3 不含以太网 API，所以由 `main/eth_link.c` 直接调用 `esp_eth`。

## 2. 引脚映射

RMII 数据线走 P4 的 **IO_MUX**（`SOC_EMAC_USE_MULTI_IO_MUX=1`），不是 GPIO Matrix，
所以只能选特定引脚。下表与 IDF `examples/ethernet/basic` 对 P4 的默认值一致：

| 信号 | GPIO |
|---|---|
| MDC | 31 |
| MDIO | 52 |
| PHY_RSTN | 51 |
| RMII_CLK (IP101 → P4, 50MHz) | 50 |
| TX_EN | 49 |
| TXD0 | 34 |
| TXD1 | 35 |
| CRS_DV | 28 |
| RXD0 | 29 |
| RXD1 | 30 |

时钟方向：IP101 自带 25MHz 晶振，向 P4 输出 50MHz REF_CLK → `EMAC_CLK_EXT_IN`。
必须用 `clock_config_out_in` 之外的正确字段，不能选 `EMAC_CLK_OUT`（否则 P4 也往外推时钟，冲突）。

## 3. 软件结构

| 文件 | 职责 |
|---|---|
| `main/eth_link.h` | 状态机 + 只读快照结构 `eth_link_status_t` |
| `main/eth_link.c` | 后台任务装 MAC/PHY/netif，事件回调更新快照 |
| `main/app_ui.c` | 底部 `NETWORK` 卡片，500ms 轮询快照 |

关键设计（对应方案 §6.3「启动不得阻塞在网络」）：

- `eth_link_start_async()` 只 `xTaskCreate` 就返回；PHY 复位、自协商、DHCP 全在后台。
- UI 线程只调 `eth_link_get_status()`，互斥锁保护，绝不等待网络。
- 事件驱动：`ETHERNET_EVENT_CONNECTED` / `IP_EVENT_ETH_GOT_IP`，不做轮询探测。

## 4. 编译期踩的坑

**`ETH_LINK_UP` / `ETH_LINK_DOWN` 枚举重名。**
`hal/eth_types.h` 已经定义了同名枚举（类型名是 `eth_link_t`）：
```c
typedef enum { ETH_LINK_UP, ETH_LINK_DOWN } eth_link_t;
```
本项目自己的枚举改用 `ETH_STATE_*` 前缀，类型名保留为 `eth_link_state_t`。
`eth_link_status_t` 是本项目的状态快照**结构体**，与 hal 的枚举不同名，可共存。
